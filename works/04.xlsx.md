# 04. 4단계: XLSX 셀 값·수식 바꾸기

`00.document-editing.md` 의 4단계 설계. 1~3단계(글자 바꾸기)와 달리 XLSX 는 **문단이 아니라 셀**이 단위라, 입력 모양과 저장 방식을 새로 정해야 한다.
라이브러리 선택은 **구현 첫 단계의 보존 실험**으로 확정한다 (아래 3절). 이 문서는 두 후보를 모두 적고, 실험 결과에 따라 고친다.

- 상태 표시: ✅ 결정됨 · 🔍 확인·결정 필요 · ⏸️ 나중에
- 작성: 2026-11-24 (설계 초안, 구현 전)

---

## 1. 범위

| 넣는 것 (4단계) | 빼는 것 (뒤 단계) |
|---|---|
| 셀 값 바꾸기: 글자, 숫자, 날짜, 참/거짓 | 행·열·시트 추가·삭제·이동, 셀 범위 옮기기 (5단계) |
| 셀 수식 바꾸기·넣기·지우기 | 글꼴·색·테두리·숫자 형식 바꾸기 (6단계) |
| 빈 셀에 값 넣기 (행·열을 밀지 않는 범위) | 새 XLSX 만들기 (7단계) |
| 같은 글자 모두 바꾸기 (글자 셀 안에서) | 차트·피벗 표·도형·메모 고치기 |
| | 수식 결과를 우리가 직접 계산하기 (아래 결정 4) |

목표 품질: **바꾼 셀 말고는 Excel 에서 열었을 때 아무것도 달라지지 않는다** (서식, 차트, 조건부 서식, 데이터 유효성, 피벗, 그림, 이름 정의).
단, 바꾼 셀을 참조하는 수식의 **결과 값은 Excel 이 열 때 다시 계산**한다 (5절).

## 2. XLSX 구조에서 알아야 할 것

```
xl/workbook.xml          시트 목록(이름·순서·숨김), 이름 정의, 계산 설정(calcPr)
xl/_rels/workbook.xml.rels  시트 ID → 파일
xl/worksheets/sheet1.xml 셀 데이터
xl/sharedStrings.xml     글자 셀의 실제 글자 (여러 셀이 같은 항목을 같이 쓴다)
xl/styles.xml            셀 서식 (숫자 형식 → 날짜인지도 여기서 안다)
xl/calcChain.xml         수식 계산 순서 (Excel 이 만든 캐시)
xl/tables/table1.xml     표(Excel Table): 범위와 머리글 이름
xl/charts/, xl/pivotTables/, xl/drawings/ …
```

### 셀 하나

```xml
<sheetData>
  <row r="4">
    <c r="A4" t="s"><v>7</v></c>                 <!-- 글자: sharedStrings 7번 항목 -->
    <c r="B4" s="3"><v>52</v></c>                 <!-- 숫자, 서식 3번 -->
    <c r="C4" s="5"><v>46350</v></c>              <!-- 서식 5번이 날짜 형식이면 2026-11-24 -->
    <c r="D4"><f>SUM(B4:C4)</f><v>46402</v></c>   <!-- 수식 + 저장된 결과 값 -->
    <c r="E4" t="inlineStr"><is><t>메모</t></is></c>  <!-- 셀 안에 직접 쓴 글자 -->
  </row>
</sheetData>
```

| 셀 종류 (`t`) | 뜻 |
|---|---|
| 없음 / `n` | 숫자 (날짜도 숫자 + 날짜 서식) |
| `s` | 공유 문자열 번호 |
| `inlineStr` | 셀 안 글자 |
| `str` | 글자를 돌려주는 수식의 결과 |
| `b` | 참/거짓 (`1`/`0`) |
| `e` | 오류 (`#DIV/0!`) |

### 조심할 함정

| 함정 | 무엇이 문제인가 | 처리 (추천) |
|---|---|---|
| **공유 문자열** | 같은 글자를 쓰는 셀들이 `sharedStrings` 항목 하나를 같이 쓴다. 항목을 고치면 **다른 셀까지 바뀐다** | 기존 항목은 절대 고치지 않는다. 새 글자는 새 항목으로 붙이고 셀 번호만 바꾼다 |
| **저장된 결과 값** | 수식 셀의 `<v>` 는 마지막으로 계산된 값이다. 값을 바꿔도 이를 참조하는 수식의 `<v>` 는 옛 값 그대로 | 5절 |
| **계산 순서 캐시** (`calcChain.xml`) | 수식을 넣거나 지우면 목록과 실제가 어긋나 Excel 이 "복구" 경고를 띄울 수 있다 | 수식을 넣거나 지우면 `calcChain.xml` 과 그 연결(rels·Content_Types)을 지운다. Excel 이 다시 만든다 |
| **공유 수식** (`<f t="shared" si="0" ref="D4:D20">`) | 첫 셀에만 수식이 있고 나머지 셀은 그것을 빌려 쓴다. 첫 셀을 고치면 아래 셀들이 깨진다 | 공유 수식의 첫 셀을 고치는 것은 거절 🔍 (빌려 쓰는 셀을 고치는 것은 그 셀만 일반 수식으로 바꾸면 된다) |
| **배열 수식** (`t="array"`) | 범위 전체가 한 수식 | 거절 |
| **병합 셀** | 값은 왼쪽 위 셀에만 있다 | 병합 범위의 왼쪽 위가 아닌 셀은 거절 ("A1 에 써라") |
| **표(Excel Table) 머리글** | 머리글 셀 글자와 `table1.xml` 의 열 이름이 다르면 Excel 이 복구 경고 | 머리글 셀을 고치면 `tableColumn name` 도 같이 고친다 |
| **날짜** | 날짜는 숫자 + 날짜 서식이다 | 결정 3 |
| **앞자리 0** (`00123`, 전화번호) | 숫자로 넣으면 `123` 이 된다 | 원래 글자 셀이면 글자로 둔다. 결정 2 |
| **시트 보호** (`sheetProtection`) | 작성자가 고치지 말라고 잠근 시트 | 거절 (사용자가 풀어서 다시 올리게) |
| **차트·피벗** | 셀을 참조하는 캐시 값을 따로 가진다 | 손대지 않는다. 차트는 Excel 이 열 때 셀 값으로 다시 그린다. 피벗은 사용자가 "새로 고침" 해야 한다 (결과에 안내) |

## 3. 라이브러리: 실험으로 정한다

| 방식 | 장점 | 단점 |
|---|---|---|
| **(A) ZIP + lxml 직접** (2·3단계와 같음) | 고친 시트·`sharedStrings` 만 다시 쓰고 나머지는 바이트 그대로 복사. 보존이 가장 확실하다. ZIP 읽기·쓰기 공통 모듈을 재사용 | 공유 문자열·날짜 서식·공유 수식·calcChain 을 직접 다뤄야 한다 |
| (B) openpyxl | 셀 읽기·쓰기가 쉽고 날짜·숫자 형식 변환을 해 준다 | 파일 전체를 읽어 다시 쓴다. 공식 문서에 **"읽지 못하는 요소(그림·차트 등)는 열었다 저장하면 사라진다"** 고 적혀 있다. 원본 보존 원칙과 정면으로 부딪힌다 |

- **추천: (A)**. 실험은 (B) 를 버릴 근거를 확인하는 용도다.
- 실험 (구현 1단계): 차트·그림·조건부 서식·데이터 유효성·피벗·메모·이름 정의·표·병합 셀이 든 시험 파일을 (B) 로 열어 셀 하나만 바꿔 저장 → ZIP 항목을 원본과 비교해 무엇이 빠지거나 바뀌는지 기록한다. 결과를 이 절에 적고 결정을 ✅ 로 바꾼다.
- (A) 를 쓰더라도 openpyxl 은 **테스트에서 결과를 읽어 확인하는 용도**로만 쓸 수 있다 (개발 의존성). 🔍

## 4. 수정 입력

1~3단계의 `old_text` → `new_text` 는 셀에 어울리지 않는다 ("B4 를 135 로" 를 글자 찾기로 하면 같은 숫자가 다른 셀에도 있을 때 모호하다).
**셀 주소로 고치는 입력**을 새로 받는다.

```json
{ "cell": "매출!B4", "value": "135" }
{ "cell": "매출!D4", "value": "=SUM(B4:C4)*1.1" }
{ "cell": "매출!E2", "value": "" }
{ "cell": "매출!F2", "value": "00123", "as_text": true }
```

| 필드 | 뜻 |
|---|---|
| `cell` | `시트이름!A1`. 시트 이름에 공백·특수 문자가 있으면 `'1분기 매출'!B4` 도 받는다. 시트 이름을 빼면 첫 번째 보이는 시트 🔍 |
| `value` | `=` 로 시작하면 수식, 빈 문자열이면 셀 비우기(서식은 남김), 나머지는 아래 규칙으로 해석 |
| `as_text` | 숫자처럼 보여도 글자로 넣기 (`00123`, `1-2`) |

### 값 해석 규칙 (결정 2·3)

| 입력 | 셀이 원래 | 넣는 값 |
|---|---|---|
| 숫자로 읽힘 (`135`, `-3.5`, `1,200`) | 숫자·빈 셀 | 숫자 (쉼표 제거) |
| 숫자로 읽힘 | **글자 셀** | 글자 그대로 (앞자리 0 등을 지키려고) |
| `TRUE`/`FALSE` | | 참/거짓 |
| `2026-11-24` 같은 ISO 날짜 | 날짜 서식 셀 | 날짜 일련번호 (서식 유지) |
| `2026-11-24` | 날짜 서식이 아닌 셀 | 글자 🔍 |
| 그 밖 | | 글자 (새 공유 문자열 항목) |

- 셀 서식(`s`)은 항상 그대로 둔다. 그래서 숫자 형식(`#,##0`, 통화, 백분율)과 글꼴이 유지된다.
- 빈 셀에 넣을 때: 행·셀 요소를 주소 순서에 맞게 끼워 넣고, 시트 범위(`dimension`)를 넓힌다. 서식은 그 행·열의 기본 서식을 따른다.

### 글자 셀 안 바꾸기 (`replace_all`)

"모든 '2024' 를 '2025' 로" 같은 요청을 위해, 1단계 입력(`old_text`, `new_text`, `replace_all`)도 **글자 셀에 한해** 받는다.

- 수식·숫자 셀은 건드리지 않는다 (수식 안 글자를 바꾸면 참조가 깨질 수 있다).
- 서식 있는 글자(셀 안에서 일부만 굵게 = rich text)는 2단계 알고리즘(run 비교)을 재사용할 수 있다. 🔍 결정 6.

## 5. 수식 결과 값 (가장 큰 문제)

B2 를 100 으로 바꾸면 `=SUM(B2:B9)` 셀의 저장된 결과는 **옛 합계 그대로**다.

- Excel·LibreOffice 는 열 때 다시 계산하게 할 수 있다 (`workbook.xml` 의 `calcPr fullCalcOnLoad="1"`). 사용자가 받아서 열어 보면 맞다.
- 그런데 **우리 쪽에서 다시 읽는 본문**(`content`, xberg 파싱)은 저장된 값을 읽으므로 옛 합계가 보인다. 에이전트가 "합계는 얼마?" 에 틀린 답을 할 수 있다.

| 선택지 | 내용 | 비용 |
|---|---|---|
| (A) 다시 계산 표시만 | `fullCalcOnLoad="1"` + 영향을 받는 수식 셀의 `<v>` 를 지운다(본문에 값 대신 빈칸 → 틀린 값보다 낫다). 결과에 "수식 결과는 Excel 에서 열 때 다시 계산된다" 안내 | 작다 |
| (B) LibreOffice 로 다시 계산 | 수정본을 headless LibreOffice 로 열어 다시 계산·저장 | 백엔드 이미지에 LibreOffice(수백 MB) 추가, LibreOffice 가 다시 저장하면서 원본 보존이 깨질 수 있다 |
| (C) Python 수식 엔진 (`formulas`, `pycel` 등) | 값만 계산해 `<v>` 에 넣는다 | 함수 지원 범위가 Excel 과 달라 틀린 값을 넣을 위험 |

- 추천: **(A)**. 틀린 숫자를 보여주는 것보다 "다시 계산 필요" 가 정직하다.
- "영향을 받는 수식" 을 정확히 찾으려면 참조 분석이 필요하다. 🔍 결정 4: 처음에는 **수식이 하나라도 바뀌었거나 값 셀이 바뀌면 문서의 모든 수식 `<v>` 를 지우기**(단순·안전) vs 같은 시트만 vs 참조 분석.
- ⏸️ (B)·(C) 는 실제로 불편할 때 다시 본다.

## 6. 도구

### `view_document_for_edit` (XLSX)

시트마다 **값이 있는 셀만** 행 단위로 보여준다.

```
[시트 1: 매출] 범위 A1:D10 · 표 "매출표"(A1:D9) · 병합 A10:B10
행 1: A1="지역" B1="1분기" C1="2분기" D1="합계"
행 2: A2="서울" B2=52 C2=48 D2==SUM(B2:C2) → 100
행 3: A3="부산" B3=31 C3=(빈 칸) D3==SUM(B3:C3) → 31
…
행 10: A10="합계" (A10:B10 병합) C10==SUM(C2:C9) → 79
[시트 2: 메모] (숨김)
행 1: A1="작성 2026-11-24"
```

- 글자는 따옴표, 숫자는 그대로, 날짜는 `2026-11-24`(서식 기준으로 변환), 수식은 `=수식 → 저장된 결과`.
- 보기 인자 `start` 는 **행 번호**로 해석한다 (2단계 결정 6, 형식마다 해석). 시트가 여럿이면 🔍 `sheet` 인자를 더할지, 순서대로 이어서 볼지.
- 아주 긴 글자 셀은 잘라서 보여주고 표시한다.

### `edit_document` (XLSX)

- `edits` 에 4절의 셀 수정과 글자 바꾸기를 섞어 받는다. 순서대로 적용, 하나라도 실패하면 전부 취소 (1단계와 같음).
- 결과: 첫 줄에 새 document_id·파일 이름, 바뀐 셀의 전/후 (`매출!B2: 52 → 100`), 수식 다시 계산 안내 (5절), 피벗이 있으면 새로 고침 안내.

### 거절하는 경우 (추가분)

| 경우 | 돌려줄 말 |
|---|---|
| 없는 시트 / 잘못된 주소 | "시트 목록: …" 을 함께 |
| 병합 범위 가운데 셀 | "병합된 셀이다. 왼쪽 위 셀(A10)에 써라" |
| 공유 수식 첫 셀, 배열 수식 | "이 셀은 여러 셀이 함께 쓰는 수식이라 아직 고칠 수 없다" |
| 보호된 시트 | "시트가 보호돼 있다" |
| 수식 문법이 명백히 깨짐 (괄호 짝 등) | "수식을 확인하라" (깊은 검사는 하지 않는다. Excel 이 열 때 판단) |
| 매크로 문서 (`.xlsm`) | 2단계 결정 10 과 같이 거절 |

## 7. 수정본 저장과 다시 읽기

2·3단계와 같다.

- 고친 시트 XML·`sharedStrings.xml`·(필요하면) `workbook.xml`·`table*.xml` 만 다시 쓰고 나머지 ZIP 항목은 그대로 복사. `calcChain.xml` 은 수식이 바뀌면 지운다.
- 수정본은 `processing` 으로 저장하고 업로드와 같은 파싱을 `DOCUMENT_EDIT_PARSE_WAIT_SECONDS` 까지 기다린다.

## 8. 검증

### 자동 테스트

| 종류 | 내용 |
|---|---|
| 단위 | 숫자·글자·날짜·참거짓 해석, 앞자리 0, 글자 셀에 숫자 넣기, `as_text` |
| 단위 | 공유 문자열: 같은 항목을 쓰는 다른 셀이 바뀌지 않는지, 새 항목 추가·개수 갱신 |
| 단위 | 빈 셀·빈 행에 넣기 (순서·`dimension`), 셀 비우기 (서식 유지) |
| 단위 | 수식 넣기·바꾸기·지우기, `<v>` 지우기·`fullCalcOnLoad`, `calcChain` 제거 |
| 단위 | 병합 셀·공유 수식·배열 수식·보호 시트 거절, 표 머리글 이름 동기화, 시트 이름 따옴표 주소 |
| 왕복 | 고치지 않은 ZIP 항목 바이트 동일, 고친 셀 말고 다른 셀 XML 동일 |
| 확인용 | (개발 의존성으로 openpyxl 을 쓰기로 하면) 수정본을 openpyxl 로 읽어 값·수식 확인 |

### 손 검증

- 2단계 결정 11 처럼 이 맥에는 Excel 이 없다. **LibreOffice Calc 로 열어** 값·수식 다시 계산 결과·차트·조건부 서식을 보고, PDF 로 바꿔 원본과 비교한다. Numbers 로도 열어 본다.
- 시험 문서(LibreOffice 로 저장, 가능하면 Excel 로 만든 파일도): 여러 시트(숨김 포함), 숫자 형식·날짜, 수식(공유 수식 포함), 표, 병합 셀, 차트, 조건부 서식, 데이터 유효성, 앞자리 0 글자 셀.
