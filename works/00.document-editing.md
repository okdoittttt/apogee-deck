# 00. 문서 직접 수정 에이전트

사용자가 올린 문서의 내용을 에이전트가 직접 고쳐서 수정본을 돌려주는 기능.
여러 날에 걸쳐 진행하므로 결정과 작업 내용을 이 파일에 계속 기록한다.

- 상태 표시: ✅ 결정됨 · 🔍 확인·결정 필요 · ⏸️ 나중에
- 시작: 2026-11-23

---

## 1. 수정할 수 있는 형식

지금 올릴 수 있는 형식은 9가지다 (`backend/app/documents/formats.py` 의 `DocumentKind`).

| 형식 | 수정 가능? | 방법 | 주의할 점 |
|---|---|---|---|
| TXT, MD, CSV | ✅ 쉬움 | 글자를 그대로 고친다 | 거의 없음 |
| DOCX | ✅ 가능 | `python-docx` + XML 직접 수정 | 한 문장이 서식 단위(run)로 여러 조각에 나뉘어 있어, 서식을 지키며 글자를 바꾸려면 조각을 다뤄야 한다 |
| XLSX | ✅ 가능 | `openpyxl` 로 셀 값·수식 수정 | 🔍 불러와서 저장하면 차트·그림 등 일부 요소가 빠질 수 있다고 알려져 있다. 시험 문서로 확인 |
| PPTX | ✅ 가능 | `python-pptx` 로 슬라이드 글자 수정 | 글자 조각 문제는 DOCX 와 같다 |
| HWPX | ⚠️ 확인 필요 | ZIP 안의 XML 을 `lxml` 로 수정 (`python-hwpx` 후보, Apache-2.0) | 🔍 수정본이 한글 프로그램에서 제대로 열리는지 확인 |
| HWPML | ⚠️ 가능 | XML 수정 | 쓰일 일이 드물다 |
| HWP (바이너리) | ❌ 사실상 불가 | 수정 라이브러리가 마땅치 않다 | HWPX 로 바꿔 다시 올리도록 안내 |
| PDF | ❌ 원본 그대로는 불가 | 글자가 좌표에 찍혀 있어 문장을 바꾸면 배치가 무너진다 | 주석·가리기 정도만 가능. 대안: 고친 내용을 DOCX/MD 로 새로 만들어 주기 |

- 지금 의존성: `python-docx`, `openpyxl`, `python-pptx` 없음. `lxml` 6.1.3 은 다른 패키지를 따라 들어와 있다.
- 새 의존성은 2주 이상 된 버전으로 고정한다.

## 2. 구현 방향 (안)

### 핵심 문제: 에이전트가 읽는 본문은 원본이 아니다

`read_document` 가 주는 본문은 파싱한 사본(Markdown, OCR 결과)이라 원본 파일의 문단·셀과 1:1 로 맞지 않는다.
그래서 수정하려면 **원본 파일을 직접 열어 "고칠 수 있는 단위"에 번호를 붙여 보여주는 보기**가 따로 필요하다.

### 도구 (추천: 형식별로 정해진 수정 도구)

- `view_document_for_edit(document_id, range)`: 고칠 수 있는 단위를 번호와 함께 보여준다.
  ```
  [p12] 2024년 매출은 120억 원이다.
  [t1 r2c3] 120
  [Sheet1!B4] =SUM(B1:B3)
  ```
- `edit_document(document_id, edits)`: 여러 수정을 한 번에 적용한다.
  - 글자 바꾸기: `{"target": "p12", "find": "120억", "replace": "135억"}`
  - 셀: `{"cell": "Sheet1!B4", "value": 135}`
  - `find` 는 대상 안에서 **정확히 한 번** 일치해야 적용한다 (엉뚱한 곳이 바뀌지 않게, str_replace 방식).
- 대안: 에이전트가 Python 코드를 짜서 실행. 유연하지만 안전한 실행 환경(샌드박스)이 없어서 지금은 쓰지 않는다.

### 결과물

- 원본은 두고 **수정본을 새 버전**으로 저장한다 (MinIO + DB 에 "어느 문서의 몇 번째 버전").
- 수정본은 다시 파싱해서 이후 `read_document` 가 수정된 내용을 읽게 한다. 프로젝트 문서면 검색 청크도 다시 만든다.
- 화면: 답변 아래 수정본 파일 칩(다운로드)과 바뀐 부분 요약(전/후).

## 3. 결정 사항 (2026-11-23)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 지원 형식 | ✅ **TXT/MD/CSV, DOCX, XLSX, PPTX 모두 지원**하는 것이 목표. 한 번에 만들면 크고 정확도를 검증하기 어려우므로 **단계별로** 하나씩 구현하고 검증한다. HWPX 는 그 뒤에 확인, PDF·HWP(바이너리)는 원본 수정 대상에서 제외. |

| 5 | 대상 문서 | ✅ **사용자가 업로드한 문서** 수정 + 에이전트가 **문서를 새로 생성**. |

- 🔍 대화 첨부는 30일 뒤 지워진다. 수정본·생성 문서도 같은 규칙을 따를지.
- ✅ 단계 순서: 3단계 PPTX, 4단계 XLSX 로 바꿨다 (2026-11-24). PPTX 는 DOCX 와 구조가 같아 2단계 코드를 재사용하고, XLSX 는 구조가 달라 보존 문제부터 풀어야 한다.
