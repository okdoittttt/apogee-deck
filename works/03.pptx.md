- 상태 표시: ✅ 결정됨 · 🔍 확인·결정 필요 · ⏸️ 나중에

## 1. 왜 XLSX 보다 먼저인가

| | PPTX | XLSX |
|---|---|---|
| 글자 구조 | 문단(`a:p`) → run(`a:r`) → 글자(`a:t`). **DOCX 와 같은 모양** | 셀 값·수식·숫자 형식·공유 문자열(`sharedStrings.xml`). 전혀 다르다 |
| 2단계 코드 재사용 | 펼치기·비교·run 쓰기를 태그 이름만 바꿔 쓴다 | 거의 못 쓴다 |
| 먼저 풀 문제 | 슬라이드 순서·도형 종류 정도 | openpyxl 보존 문제, 수식 계산 값 처리 |

PPTX 를 먼저 하면 2단계 알고리즘이 **두 번째 형식에서도 통하는지** 바로 검증된다.

## 2. 범위

| 넣는 것 (3단계) | 빼는 것 (뒤 단계) |
|---|---|
| 슬라이드의 텍스트 상자·자리 표시자(제목, 본문, 부제목 등) 글자 | 슬라이드·도형 추가·삭제·이동 (5단계) |
| 그룹 도형 안의 텍스트 상자 (중첩 포함) | 글꼴·색·크기 바꾸기 (6단계) |
| 표 칸 안 글자 | 새 PPTX 만들기 (7단계) |
| 🔍 발표자 노트 (아래 결정 1) | 차트 안 글자 (별도 파일 `ppt/charts/`) |
| `replace_all` | SmartArt (`ppt/diagrams/` 데이터 + 그림 캐시 두 벌) |
| | 슬라이드 마스터·레이아웃의 글자 (모든 슬라이드에 영향) |
| | 수식, WordArt 효과 |

목표 품질: **바꾼 글자 말고는 PowerPoint 에서 열었을 때 아무것도 달라지지 않는다** (배치, 서식, 그림, 애니메이션, 전환 효과).

## 3. PPTX 구조에서 알아야 할 것

### 슬라이드 순서

- 슬라이드 파일 이름 번호(`ppt/slides/slide3.xml`)는 **화면 순서가 아니다**. 슬라이드를 옮기거나 지우면 어긋난다.
- 순서는 `ppt/presentation.xml` 의 `p:sldIdLst` → `r:id` → `ppt/_rels/presentation.xml.rels` 의 대상 파일로 정한다.
- 숨긴 슬라이드(`<p:sld show="0">`)도 고칠 수 있게 보여주되 `(숨김)` 으로 표시한다.

### 슬라이드 안의 글자

```xml
<p:sld>
  <p:cSld><p:spTree>
    <p:sp>                                   <!-- 도형 (텍스트 상자, 자리 표시자) -->
      <p:nvSpPr><p:cNvPr id="2" name="제목 1"/>…<p:nvPr><p:ph type="title"/></p:nvPr></p:nvSpPr>
      <p:txBody>
        <a:bodyPr/><a:lstStyle/>
        <a:p>                                <!-- 문단 -->
          <a:r><a:rPr b="1"/><a:t>2024 하반기</a:t></a:r>
          <a:r><a:t> 영업 보고</a:t></a:r>
        </a:p>
      </p:txBody>
    </p:sp>
    <p:grpSp>…도형 묶음 (안에 p:sp, p:grpSp 가 또 있다)…</p:grpSp>
    <p:graphicFrame>…<a:tbl><a:tr><a:tc><a:txBody><a:p>…</a:p></a:txBody></a:tc></a:tr></a:tbl></p:graphicFrame>
    <p:pic>…그림 (글자 없음)…</p:pic>
  </p:spTree></p:cSld>
</p:sld>
```

DOCX 와 비교:

| DOCX (`w:`) | PPTX (`a:`, DrawingML) | 비고 |
|---|---|---|
| `w:p` | `a:p` | 문단 |
| `w:r` / `w:rPr` / `w:t` | `a:r` / `a:rPr` / `a:t` | run·서식·글자. 구조 같음 |
| `w:tab` | `a:t` 안의 `\t` 글자 | PPTX 는 탭이 그냥 글자 |
| `w:br` | `a:br` (자체 `a:rPr` 를 가짐) | 줄바꿈 |
| `w:fldSimple`, `w:fldChar` | `a:fld` (슬라이드 번호, 날짜) | 필드: 벽으로 처리 |
| `w:pPr` | `a:pPr` | 문단 서식 (글머리표 수준 `lvl` 등) |
| — | `a:endParaRPr` | 문단 끝 서식. 글자 없음, 그대로 둔다 |
| `w:hyperlink` (run 을 감쌈) | `a:rPr` 안의 `a:hlinkClick` | **링크가 run 의 서식 속성**이다. 경계는 "링크 있는 run ↔ 없는 run" |
| `xml:space="preserve"` | 필요 없음 | DrawingML 은 공백을 그대로 둔다 |
| `w:ins`/`w:del` | 없음 | PPTX 는 변경 내용 추적이 없다 |

### 글자 수가 바뀔 때 (자동 맞춤)

- 텍스트 상자에는 "글자가 넘치면 줄이기"(`a:normAutofit fontScale="…"`) 나 "도형 크기 맞추기"(`a:spAutoFit`) 설정이 있다.
- 이 값은 **PowerPoint 가 열 때가 아니라 편집할 때** 다시 계산한다. 우리가 글자를 늘리면, 파일을 열었을 때 글자가 상자 밖으로 넘쳐 보일 수 있다.
- 우리가 글꼴 크기를 계산할 수는 없으므로(글꼴 측정 필요), 🔍 결정 4: 글자가 많이 늘어나면 결과에 "상자를 넘칠 수 있다" 고 알려 에이전트가 사용자에게 전하게 한다.

## 4. 2단계 코드 재사용

2단계 `editing/docx.py` 는 WordprocessingML(`w:`) 태그를 직접 다룬다 (`_tokens`, `_write_run`, `_flatten`, `_ParagraphEditor`).

| 부분 | 재사용 방법 |
|---|---|
| ZIP 읽기·쓰기 (고친 XML 만 다시 쓰고 나머지 바이트 복사), XML 파싱·직렬화 | 그대로 공통 모듈로 옮긴다 |
| 글자 단위 비교·통째로 바꾸기 기준(`WHOLE_REPLACE_RATIO`), `old_text` 찾기·`replace_all`·전부 취소 | 그대로 |
| 문단 펼치기(`_flatten`), run 읽기·쓰기(`_tokens`, `_write_run`) | 태그 이름과 규칙이 달라 **형식별로 둔다**. 다만 "글자 목록(`_Glyph`) ↔ 편집기" 사이의 경계를 같게 맞춘다 |
| 보기 문자열·범례 | 형식별 |

- 🔍 결정 5: 공통 부분을 `editing/ooxml.py` 같은 모듈로 **먼저 뽑아낸 뒤**(2단계 테스트로 동작이 같은지 확인) PPTX 를 얹을지, PPTX 를 복사로 먼저 만들고 나중에 합칠지.
  추천: **먼저 뽑아낸다.** 같은 알고리즘이 두 벌이 되면 한쪽만 고쳐지는 일이 생긴다. 2단계 테스트(44개)가 리팩터링의 안전망이 된다.

## 5. 글자 모델

2단계와 같다. 문단을 글자 목록으로 펼치고, 고칠 수 없는 자리는 **벽**(`￼`)으로 둔다.

| 요소 | 처리 |
|---|---|
| `a:r` 안의 `a:t` | 글자 (`\t` 포함) |
| `a:br` | `\n`. 바꾸기 범위에 걸리면 거절 (2단계 결정 4 와 같이 줄바꿈은 아직 다루지 않는다) |
| `a:fld` (슬라이드 번호·날짜) | 벽 |
| 링크가 있는 run ↔ 없는 run 경계, 링크 주소가 다른 run 경계 | 벽처럼 넘지 못한다 (링크 **안**에서만 바꾸기 허용) |
| 수식(`a14:m`, `mc:AlternateContent` 안) | 벽 |
| 넣는 글자의 서식 | 바로 앞 글자의 run (`a:rPr` 복사). 문단 맨 앞이면 바로 뒤 글자의 run |
| 빈 문단 | 보기에 보이지만 바꿀 글자가 없다 (`a:endParaRPr` 만) |

## 6. 도구

새 도구 없이 2단계 도구를 넓힌다.

### `view_document_for_edit` (PPTX)

```
[p1] (슬라이드 1 · 제목) 2024 하반기 영업 보고
[p2] (슬라이드 1 · 부제목) 영업팀
[p3] (슬라이드 2 · 본문) 매출 120억 원 달성
[p4] (슬라이드 2 · 본문 · 수준 2) 서울 52억, 부산 31억
[p5] (슬라이드 3 · 표1 2행 2열) 52억
[p6] (슬라이드 3 · 텍스트 상자 "메모") 단위: 억 원 ￼
[p7] (슬라이드 3 · 노트) 이 슬라이드에서는 서울 성장을 강조한다
```

- 번호는 **슬라이드 순서대로 이어 매긴다** (`p1, p2, …`). 2단계의 `paragraph` 필드(`"p5"`)를 그대로 쓰기 위해서다.
  🔍 결정 2: 슬라이드별 번호(`s3p5`)도 생각했지만, 도구 입력과 접두어 검사(`[p12]`)를 2단계와 같게 두는 쪽이 에이전트 실수가 적다.
- 위치 표시: 슬라이드 번호, 자리 표시자 종류(제목·부제목·본문 등 `p:ph type`), 이름 있는 텍스트 상자는 `텍스트 상자 "이름"`, 글머리표 수준(`a:pPr lvl`, 1 보다 클 때만), 표 위치, `(숨김)`, `노트`.
- 보기 인자 `start` 는 2단계 결정 6 처럼 문단 번호로 해석한다.

### `edit_document` (PPTX)

입력은 2단계와 똑같다 (`old_text`, `new_text`, `replace_all`, `paragraph`).

- 찾는 단위는 문단 하나 안 (2단계와 같음). 슬라이드를 넘는 것은 당연히 거절.
- 결과: 첫 줄에 새 document_id·파일 이름, 바뀐 문단의 전/후와 위치(슬라이드 번호). 자동 맞춤 경고(결정 4).

### 거절하는 경우 (추가분)

| 경우 | 돌려줄 말 |
|---|---|
| 범위가 슬라이드 번호·날짜 필드·수식에 걸림 | "고칠 수 없는 요소가 있다. 범위를 좁혀라" |
| 범위가 링크 경계를 넘음 | "링크 글자와 일반 글자를 한 번에 고칠 수 없다" |
| 매크로 문서 (`.pptm`) | 2단계 결정 10 처럼 `[Content_Types].xml` 의 `macroEnabled` 로 거절 |
| 차트·SmartArt 글자를 고치려 함 | 보기에 나오지 않으므로 `old_text` 를 못 찾음. 찾지 못했을 때 "차트·SmartArt 글자는 아직 고칠 수 없다" 는 안내를 덧붙일지 🔍 |

## 7. 수정본 저장과 다시 읽기

2단계와 같다.

- 고친 슬라이드(·노트) XML 만 다시 쓰고 나머지 ZIP 항목은 바이트 그대로 복사.
- 수정본은 `processing` 으로 저장하고 업로드와 같은 파싱(`schedule_parse`)을 `DOCUMENT_EDIT_PARSE_WAIT_SECONDS` 까지 기다린다 (2단계 결정 2).
- 파싱 결과에 발표자 노트가 들어가는지(`speaker_notes`)는 지금 업로드 파서 동작을 그대로 따른다.

## 8. 검증

### 자동 테스트

| 종류 | 내용 |
|---|---|
| 단위 (XML 조각) | run 여러 개에 걸친 바꾸기, 굵은 글자 일부만 바꾸기, 넣기·지우기 서식 상속, 빈 run 정리 |
| 단위 | `a:br`·`a:fld` 걸침 거절, 링크 안/경계(`a:hlinkClick`), 수식 벽, `a:endParaRPr` 유지 |
| 단위 | 슬라이드 순서(파일 이름 번호와 다른 순서인 시험 문서), 그룹 도형 중첩, 표 칸, 숨긴 슬라이드, 노트 |
| 왕복 | 고치지 않은 ZIP 항목이 바이트까지 같은지, 고친 문단 말고 다른 도형 XML 이 같은지 |
| 공통화 | 4절 공통 모듈로 옮긴 뒤 2단계 DOCX 테스트가 모두 그대로 통과하는지 |

### 손 검증

- 2단계 결정 11 과 같이 이 맥에는 PowerPoint 가 없다. **LibreOffice Impress 로 원본·수정본을 PDF 로 바꿔 비교**하고, Keynote 로도 열어 본다.
- 시험 문서: LibreOffice Impress(또는 Keynote 에서 PPTX 로 내보내기)로 저장한 PPTX. 제목·본문 자리 표시자, 굵게 섞인 문장, 글머리표 수준 2, 표, 링크, 그림, 슬라이드 번호 필드, 그룹 도형, 노트, 숨긴 슬라이드, **슬라이드 순서를 바꾼 문서**를 넣는다.
- PowerPoint 확인은 PowerPoint 가 있는 곳에서 따로.
