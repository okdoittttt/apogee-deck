# 설계 결정 기록 (ADR)

중요한 설계 결정을 하나에 한 문서로 남깁니다. 나중에 "왜 이렇게 했지?" 라는 질문에 답하기 위해서입니다.

## 목록

| 번호 | 결정 | 상태 |
|---|---|---|
| [0001](0001-history-in-checkpointer.md) | 모델 입력 이력은 checkpointer 에, 화면 이력은 messages 테이블에 | 채택 |

## 언제 쓰나

- 대안이 둘 이상 있었고, 하나를 고른 이유가 코드만 봐서는 드러나지 않을 때
- 되돌리기 어려운 결정일 때 (저장 구조, 계층, 외부 서비스 선택)
- 같은 질문이 두 번 나왔을 때

작은 결정은 기능 문서의 "설계 결정" 칸에 씁니다. 거기서 길어지면 ADR 로 옮깁니다.

## 규칙

- 파일 이름은 `NNNN-<짧은-영문-제목>.md` 입니다. 번호는 다시 쓰지 않습니다.
- 결정을 바꾸면 기존 문서를 지우지 않습니다. 상태를 `대체됨 (→ NNNN)` 으로 바꾸고 새 ADR 을 씁니다.
- 상태: `제안` → `채택` → (`대체됨` 또는 `폐기`)

## 틀

```markdown
# NNNN. <결정을 한 문장으로>

- 상태: 채택
- 날짜: YYYY-MM-DD
- 관련 코드: `backend/app/...`

## 배경
어떤 문제가 있었고, 무엇이 제약이었나.

## 결정
무엇을 하기로 했나.

## 검토한 대안
- 대안 A: 내용. 고르지 않은 이유.

## 결과
좋아진 점, 감수한 점, 이 결정 때문에 지켜야 하는 것.
```
